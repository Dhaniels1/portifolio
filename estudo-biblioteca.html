OBJETIVO E CONTEXTO

Modelar um catálogo e suas regras.

O projeto foi desenvolvido para uma atividade acadêmica de Desenvolvimento Web III. O objetivo era estruturar uma API com regras de negócio, persistência de dados e relacionamentos entre livros, autores e categorias.

O desafio adicional foi tornar o resultado acessível para demonstração, oferecendo uma página pública de consulta em vez de exigir que cada visitante utilize um cliente de API.

FUNCIONALIDADES

Como a solução funciona

01

Consultar o acervo

A interface pública permite buscar e filtrar livros, autores e categorias, sem acesso às operações de escrita.

02

Gerenciar recursos via API

Endpoints REST implementam operações de criação, leitura, atualização e exclusão, respeitando validações e relacionamentos.

03

Proteger operações

Laravel Sanctum utiliza autenticação por token; as operações de escrita dependem de autorização.

IMPLEMENTAÇÃO

Backend com regras explícitas.

LaravelPHPMySQLEloquentSanctumBlade

A implementação utiliza Laravel 12 e PHP, modelos Eloquent e migrações de banco de dados. O README documenta o uso de MySQL na instalação, além de SQLite e MySQL na integração contínua.

O projeto documenta tratamento de entradas inválidas, conflitos ao excluir registros associados, restrições de ISBN e expiração dos tokens. A interface pública usa Blade, CSS e JavaScript para consultar a API.

Existe uma carga de dados de demonstração para permitir a navegação sem inserir dados reais ou conceder acesso administrativo.

QUALIDADE E TRANSPARÊNCIA

Testes e acesso controlado.

O repositório inclui testes automatizados, workflow de CI e coleção Postman. As leituras de catálogo são públicas; as mutações exigem autenticação, mantendo a demonstração separada das rotinas administrativas.

O endereço publicado no Render pode ter tempo adicional de inicialização no plano gratuito. A disponibilidade em tempo real deve ser verificada no momento de cada demonstração.

LIMITES E PRÓXIMAS MELHORIAS

Evoluções possíveis.

Expandir a documentação de exemplos de request/response, capturas reais do frontend e um diagrama de entidades para facilitar o entendimento por recrutadores e professores.

A interface visual é de consulta; demonstrações de operações autenticadas devem ocorrer em ambiente controlado, sem expor credenciais ou tokens.
